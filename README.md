# «ЛингваПро» — Telegram-бот продавца языковых курсов на MCP

Учебный проект: Telegram-бот на **aiogram 3**, который консультирует клиентов языкового центра и оформляет заявки. Все факты о курсах, ценах, скидках и условиях хранятся в **SQLite** и доступны боту только через **MCP-сервер** (Model Context Protocol).

Главная идея: LLM не «помнит» каталог и не получает его целиком в промпт. Модель решает, какой инструмент вызвать, а MCP-сервер возвращает компактный JSON. Это дешевле по токенам, чем RAG с большим контекстом, и исключает выдуманные цены.

---

## Что умеет бот

- подбирает курсы по языку, уровню и бюджету;
- показывает программу, преподавателя, длительность и свободные группы;
- считает цену с промокодом и рассрочкой (3/6/12 месяцев);
- отвечает на вопросы об оплате, пропусках, сертификате и формате обучения из базы знаний;
- создаёт заявку, когда у клиента есть имя, контакт и выбранный курс;
- считает заказ из нескольких курсов, применяя промокод ровно к одному курсу;
- показывает и меняет заявку: состав заказа, скидку, комментарий, время занятий;
- не создаёт дубли заявок при повторном сообщении в течение 15 минут;
- напоминает о заявке через 2 минуты, если диалог закончился без заявки;
- ведёт короткую историю диалога отдельно для каждого чата;
- даёт выбрать длину ответа командой `/length` — отдельно для каждого чата;
- автоматически продолжает ответ, если модель остановилась по лимиту токенов;
- показывает каталог командой `/courses` напрямую через MCP, без вызова LLM.

Пример реального диалога:

> **Пользователь:** Хочу подтянуть разговорный английский. Сколько стоит и есть ли рассрочка?
>
> **Бот:** Курс «Разговорный английский» стоит 21 990 рублей. Рассрочка есть на 3, 6 и 12 месяцев. При рассрочке на 6 месяцев итоговая цена будет 23 090 рублей, ежемесячный платёж — 3 848 рублей. Хотите записаться?

## Архитектура

```text
Telegram
   │
   ▼
aiogram-бот (telegram_bot/)
   ├── handlers/        команды и сообщения
   ├── history.py       последние 12 сообщений на чат
   ├── preferences.py   выбранная длина ответа на чат
   ├── reminders.py     отправка напоминаний по расписанию сервера
   └── agent.py         цикл LLM → tool call → ответ → продолжение
            │
            │ MCP Client (Streamable HTTP)
            ▼
MCP-сервер (mcp_server/)  http://127.0.0.1:8000/mcp
   ├── tools.py         16 инструментов
   ├── pricing.py       расчёт скидки, рассрочки и заказа
   ├── database.py      SQLite-запросы
   └── seed.py          стартовый каталог
            │
            ▼
      data/courses.db
```

Почему так:

- **одна ответственность** — бот не знает SQL, сервер не знает Telegram;
- **инструменты вместо RAG** — модель получает только нужные 2–5 записей, а не весь документ;
- **локальный сервер** — каталог и заявки остаются в локальной SQLite, без внешнего MCP-хостинга; текст диалога, как обычно, отправляется выбранному LLM-провайдеру;
- **честные ответы** — если инструмент вернул ошибку, модель обязана сказать об этом, а не придумать цену.

## MCP-инструменты

| Инструмент | Аргументы | Что возвращает |
|---|---|---|
| `search_courses` | `language`, `level`, `max_price` | компактный список курсов с `id`, ценой и длительностью |
| `get_course_details` | `course_id` | описание, программу, преподаватель, свободные группы |
| `calculate_course_price` | `course_id`, `promo_code`, `installment_months` | базовую цену, скидку, итог, платёж в месяц и доступные сроки рассрочки |
| `calculate_order_price` | `course_ids`, `promo_code`, `apply_to_course_id` | цены по позициям заказа, общий итог и варианты применения скидки |
| `list_promotions` | — | активные промокоды, проценты и правило «скидка на один курс» |
| `search_faq` | `query`, `limit` | до 5 ответов из базы знаний |
| `create_lead` | `name`, `contact`, `course_id`, `preferred_time`, `comment`, `promo_code` | ID заявки, её итог и признак дубля |
| `get_lead_details` | `contact`, `limit` | заявки клиента: курсы, промокод, скидка, итог, статус |
| `update_lead` | `lead_id`, `comment`, `preferred_time`, `status`, `course_id`, `promo_code` | обновлённую заявку: курс, скидку, итог |
| `cancel_lead` | `lead_id` | отметку «заявка отменена» с записью в журнале |
| `apply_promo_to_lead` | `contact`, `promo_code`, `course_id` | пересчитанный заказ со скидкой на одном курсе |
| `schedule_lead_reminder` | `chat_id`, `delay_seconds` | время напоминания о заявке для чата |
| `cancel_lead_reminder` | `chat_id`, `reason` | признак отмены напоминания |
| `get_due_reminders` | `limit` | созревшие напоминания и текст для отправки |
| `complete_lead_reminder` | `chat_id` | отметка «напоминание отправлено» |
| `get_lead_reminder_status` | `chat_id` | состояние напоминания чата |

Одиннадцать инструментов выбирает модель. Пять инструментов напоминаний вызывает сам бот по таймеру — они не входят в описание инструментов для LLM и не тратят токены на выбор.

Все инструменты возвращают строку JSON с полем `ok`. Ошибки тоже оформлены как JSON: модель может объяснить их пользователю, а не падать.

### Промокод действует на один курс

Правило центра: промокод применяется ровно к одному курсу, а не ко всему заказу. Раньше оно нигде не было зафиксировано, и модель, считая заказ из двух курсов, складывала два расчёта со скидкой и называла выдуманную сумму. Теперь правило обеспечено на трёх уровнях:

| Уровень | Как |
|---|---|
| Данные | в описании промокода и в FAQ прямо написано «только на один курс» |
| Расчёт | `calculate_order_price` считает заказ на сервере и применяет скидку к одной позиции |
| База | `apply_promo_to_lead` снимает скидку с остальных заявок контакта и пересчитывает `total_price` |

Модель не обязана помнить арифметику: она передаёт состав заказа и получает готовые `lines`, `total` и `options` — что будет, если применить скидку к каждому из курсов. Если клиент не сказал, какой курс дешевле, бот показывает самый выгодный вариант (скидка на дорогой курс) и спрашивает подтверждение.

### Заявку меняют инструменты, а не обещания

`get_lead_details` возвращает реальный состав заказа по контакту, поэтому бот больше не путает курсы между заявками и не пересказывает их по памяти диалога. Изменяют заявку только инструменты: `update_lead` (скидка, снятие скидки, другой курс, комментарий, время, статус), `apply_promo_to_lead` (перенос скидки между курсами) и `cancel_lead` (отмена). Все три пишут строку в `leads.history`, поэтому изменение видно в базе.

Агент подстраховывает модель: если клиент просит изменить заявку, а в ответе есть обещание («передам менеджеру», «исправлю», «применю скидку») и при этом ни один инструмент заявки не отработал, агент один раз возвращает модель к работе и требует выполнить просьбу инструментом. Обещание без записи в базу не уходит в Telegram.

Клиент часто оставляет несколько контактов одной строкой («olga@mail.ru, +79055553322»), а спрашивает, называя только телефон. Поэтому заявка ищется сначала по точному совпадению, а затем по вхождению названного контакта в сохранённый — иначе бот отвечал бы «заявок нет» на реальные заявки.

### Напоминание о заявке

Если пользователь перестал отвечать и заявку не оставил, бот сам напоминает о записи. Для урока пауза — 2 минуты после последнего сообщения.

Как это работает:

1. После каждого ответа бота вызывается `schedule_lead_reminder` — таймер чата отсчитывает `REMINDER_DELAY_SECONDS` заново.
2. Сервер хранит расписание в таблице `reminders` и считает срок сам, поэтому перезапуск бота запланированные напоминания не теряет.
3. Бот раз в `REMINDER_POLL_SECONDS` опрашивает `get_due_reminders` и отправляет текст в нужный чат, после чего отмечает напоминание через `complete_lead_reminder`.
4. `create_lead` отменяет напоминание: созданная заявка снимает запись в `reminders`.
5. Напоминание отправляется один раз за диалог; `/clear` сбрасывает состояние, и оно снова становится возможным.
6. `/status` показывает состояние напоминания: не запланировано, запланировано на…, уже отправлено или не требуется.

Так сервер остаётся единственным источником правды о заявках и расписании, а бот — только отправителем.

### База данных

SQLite, файл `data/courses.db`, создаётся при первом запуске.

| Таблица | Назначение |
|---|---|
| `courses` | курсы: язык, уровень, цена, формат, длительность, преподаватель |
| `modules` | программа курса по модулям |
| `groups` | группы: расписание, свободные места, формат |
| `promos` | промокоды и скидки |
| `faq` | база знаний по обучению и оплате |
| `leads` | заявки клиентов: имя, контакт, курс, промокод, скидка, итог, журнал изменений |
| `reminders` | расписание напоминаний о заявке: срок, статус, отметка о заявке |
| `lead_details` | вьюха для менеджера: заявка с названием курса, ценой и скидкой в рублях |

Стартовые данные лежат в `mcp_server/seed.py`: 7 курсов, 21 модуль, 8 групп, 3 промокода и 14 вопросов FAQ. Повторный запуск не дублирует записи, но обновляет условия промоакций — правило «промокод на один курс» живёт именно в описании промокода, и старые базы получают его автоматически.

Схема заявки расширяется на месте: `initialize()` досоздаёт колонки `promo_code`, `discount_percent`, `total_price` и `history`, если база создана более ранней версией проекта. Существующие заявки при этом сохраняются.

В `leads.history` каждая заявка хранит короткий журнал: создание, применение и снятие скидки, замену курса, отмену — с датой и итоговой суммой. Так видно историю работы с клиентом прямо в таблице, а не только в логах бота.

Linux/macOS:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 2. Зависимости

```bash
pip install -r requirements.txt
```

Для тестов:

```bash
pip install -r requirements-dev.txt
```

### 3. Настройки

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен Telegram-бота от @BotFather |
| `OPENAI_API_KEY` | да | ключ ProxyAPI или другого OpenAI-совместимого API |
| `OPENAI_BASE_URL` | да | например `https://api.proxyapi.ru/v1` |
| `DEFAULT_MODEL` | да | основная модель, например `openai/gpt-4.1-mini` |
| `FALLBACK_MODEL` | нет | запасная модель при ошибке основной |
| `TELEGRAM_PROXY` | нет | прокси для Telegram, например `http://127.0.0.1:10809` |
| `MCP_URL` | нет | по умолчанию `http://127.0.0.1:8000/mcp` |
| `MCP_HOST`, `MCP_PORT` | нет | адрес MCP-сервера, по умолчанию localhost:8000 |
| `HISTORY_LIMIT` | нет | число сообщений истории, по умолчанию 12 |
| `MAX_TOOL_ROUNDS` | нет | максимум шагов агента, по умолчанию 5 |
| `MAX_CONTINUATIONS` | нет | сколько раз продолжать оборванный ответ, по умолчанию 2 |
| `PREFERENCES_FILE` | нет | файл настроек чатов, по умолчанию `data/preferences.json` |
| `REMINDER_DELAY_SECONDS` | нет | пауза перед напоминанием о заявке, по умолчанию 120; 0 — выключить |
| `REMINDER_POLL_SECONDS` | нет | как часто бот опрашивает сервер о напоминаниях, по умолчанию 15 |
| `REMINDER_TEXT` | нет | текст напоминания; пусто — встроенный текст по умолчанию |

`.env` уже добавлен в `.gitignore` и не должен попадать в репозиторий.

## Запуск

### Вариант 1: всё одной командой

```bash
python run_all.py
```

Скрипт поднимает MCP-сервер отдельным процессом, ждёт открытия порта и запускает бота. При выходе сервер останавливается. Если сервер уже запущен, второй экземпляр не создаётся.

### Вариант 2: два терминала

Терминал 1:

```bash
python run_server.py
```

Терминал 2:

```bash
python run_bot.py
```

Эквивалентные команды:

```bash
python -m mcp_server
python -m telegram_bot
```

При первом запуске автоматически появятся:

- `data/courses.db` — каталог, FAQ и заявки;
- `data/history.json` — история диалогов;
- `data/preferences.json` — выбранная длина ответов по чатам;
- `data/bot.log` — лог бота.

## Команды бота

| Команда | Действие |
|---|---|
| `/start` | приветствие и с чего начать |
| `/courses` | каталог и цены напрямую из MCP, без LLM |
| `/length` | длина ответов: `short`, `normal` или `long` |
| `/help` | возможности и список команд |
| `/clear` | очистить историю текущего чата |
| `/status` | статус MCP, история, длина ответов, модель |

Обычный текст уходит в агент. Нетекстовые сообщения получают вежливую подсказку.

### Длина ответов и автопродолжение

Команда `/length` действует только на текущий чат и сохраняется в `data/preferences.json`:

| Режим | Лимит ответа | Когда использовать |
|---|---|---|
| `short` | 350 токенов | короткая справка |
| `normal` | `DEFAULT_MAX_TOKENS` из `.env` (650) | обычный диалог |
| `long` | 1600 токенов | подробный разбор программы |

Примеры:

```text
/length
/length long
/length короткий
```

Если модель возвращает `finish_reason="length"`, агент автоматически просит продолжить ответ с места обрыва и склеивает части. Число продолжений ограничено `MAX_CONTINUATIONS`, поэтому даже «длинный» режим не может разрастись бесконечно. Если после всех продолжений ответ всё ещё обрезан, в конце добавляется многоточие, а в лог пишется предупреждение.

Важно: `/length` управляет длиной **ответа**, а не «окном контекста» модели. Память диалога по-прежнему ограничена `HISTORY_LIMIT` и `HISTORY_MAX_CHARS`.

## Тестирование

### Автотесты

```bash
pytest -q
```

Покрыто 76 проверок:

- расчёт цены, скидок и рассрочки;
- расчёт заказа из нескольких курсов: скидка ровно на одной позиции, варианты применения;
- фильтрация каталога и поиск по алиасам (`english` → «Английский»);
- карточка курса с программой и группами;
- поиск по FAQ и создание/дедупликация заявок;
- заявка с промокодом: сохранение скидки и итога в базе;
- правило «промокод на один курс» в данных и его обновление в старой базе;
- изменение заявки (курс, промокод, снятие скидки, комментарий) и перенос скидки между заявками клиента;
- отмена заявки с сохранением записи и журнала;
- журнал `leads.history`: создание, скидка, правки и отмена видны в базе;
- поиск заявки по любому из контактов, оставленных одной строкой;
- ограничение и сохранение истории диалога;
- настройки длины ответа: режимы, алиасы, изоляция чатов, восстановление файла;
- команда `/length`: показ текущего режима и переключение;
- агентный цикл с поддельными LLM и MCP;
- агент не отдаёт ответ с обещанием «передам менеджеру», если заявку так и не изменили;
- автопродолжение ответа при `finish_reason="length"` и лимит продолжений;
- напоминания о заявке: расписание, перезапуск таймера, отмена при заявке, однократная отправка;
- интеграционный тест: реальный MCP-сервер, реальный клиент, вызов всех инструментов.

Ожидаемый результат: `76 passed`.

### Живая проверка MCP + LLM

Сначала запустите MCP-сервер, затем:

```bash
python scripts/smoke_llm.py
```

Скрипт печатает список инструментов сервера и прогоняет три вопроса. Он не создаёт заявок и не меняет базу. В логах видно, какие инструменты вызвала модель.

### Ручной чек-лист в Telegram

1. `/start` — приходит приветствие.
2. `/courses` — список из 7 курсов с ценами.
3. `/length` — показывает текущий режим; `/length long` — подтверждает переключение.
4. Задайте подробный вопрос — длинный ответ приходит целиком, без обрыва на полуслове.
5. «Хочу разговорный английский, сколько стоит и есть рассрочка?» — бот называет 21 990 ₽ и варианты рассрочки.
6. «Какие курсы для начинающих до 18 000?» — бот предлагает «Английский с нуля»; при корректном фильтре также может предложить немецкий A1.
7. «Можно ли пропустить занятие?» — ответ про запись и отработку.
8. «Какие акции?» — активные промокоды из базы, без выдуманных условий.
9. «Меня зовут Ирина, телефон +7 999 123-45-67, запишите на разговорный английский вечером» — бот подтверждает и создаёт заявку.
10. Повторите заявку с тем же контактом — дубль не создаётся.
11. `/status` — MCP подключён, видно количество сообщений, режим длины и состояние напоминания.
12. `/clear` — история очищена, но выбранный режим `/length` сохраняется.
13. Задайте вопрос и замолчите на 2 минуты — бот сам пришлёт одно напоминание о заявке. Создайте заявку до паузы — напоминания не будет.
14. «Промокод START10 действует на весь заказ или на один курс?» — бот отвечает «на один курс», ссылаясь на данные, а не на догадки.
15. Оставьте две заявки на разные курсы и спросите итог со скидкой — бот назовёт скидку на одном курсе и общий итог заказа, а не сумму двух скидок.
16. Попросите «сделайте скидку на более дорогой курс» — бот применит промокод инструментом, назовёт новый итог, а в базе изменятся `promo_code`, `discount_percent` и `total_price`.
17. Попросите «отмените мою заявку на немецкий» — бот отменит её `cancel_lead`, заявка получит статус `cancelled` и строку в `history`.
18. Если бот ответит «передам менеджеру», а инструмент не сработает, агент заставит его выполнить изменение; в Telegram такой ответ без записи в базу не уходит.

### Как менеджер видит заявки и скидки

В таблице `leads` лежит `course_id`, поэтому `SELECT *` показывает цифры, которые
без каталога не прочитать. Для просмотра есть готовая вьюха `lead_details` и скрипт:

```bash
python scripts/show_leads.py
```

Он печатает по заявке в строку: имя, контакт, курс, базовую цену, промокод, скидку
в рублях, итог и статус. Тот же запрос руками:

```bash
python -c "import sqlite3; [print(r) for r in sqlite3.connect('data/courses.db').execute('SELECT id, name, course, base_price, promo_code, discount_percent, discount_rub, total_price, status FROM lead_details')]"
```

Поля `discount_percent`, `discount_rub` и `promo_code` непустые ровно у той заявки,
которой выдана скидка, а `history` содержит журнал: кто и когда применил промокод,
перенёс заявку на другой курс или отменил её.

## Экономия токенов

Проект специально не использует RAG и тяжёлые фреймворки:

- в промпте нет каталога и FAQ — только правила продажи;
- 11 инструментов с короткими описаниями; остальные 5 (напоминания) бот вызывает сам и модели не показывает;
- арифметику заказа считает сервер (`calculate_order_price`), а не модель: итог не зависит от текста ответа;
- результаты инструментов — компактный JSON без пробелов;
- результат обрезается до `MAX_TOOL_RESULT_CHARS` (5 000 символов);
- история ограничена 12 сообщениями и 9 000 символами;
- температура 0.3 и `max_tokens=650` в обычном режиме — ответы короче и стабильнее;
- режим `/length long` включается вручную и только для одного чата;
- автопродолжение работает не больше `MAX_CONTINUATIONS` раз;
- цикл инструментов ограничен 5 раундами, затем модель обязана ответить без вызовов;
- `/courses` вообще не тратит токены: бот форматирует ответ MCP сам.

## Устойчивость к ошибкам

- Нет MCP-сервера — бот запускается, `/start` и `/help` работают, на запросы отвечает понятным сообщением.
- Нет связи с LLM — пользователь получает «попробуйте ещё раз», подробности в `data/bot.log`.
- Telegram отклонил токен или запущена вторая копия — в логе понятная причина, процесс завершается.
- Битый `history.json` — история сбрасывается, бот продолжает работу.
- Битый `preferences.json` — настройки сбрасываются на `normal`, бот продолжает работу.
- Ответ оборвался по лимиту — агент автоматически продолжает его, но не больше `MAX_CONTINUATIONS` раз.
- Неверный промокод или срок рассрочки — инструмент возвращает JSON-ошибку, модель объясняет её.
- Повторная заявка — возвращается существующая запись, дубль не создаётся.
- Клиент просит скидку на все курсы заказа — сервер применит её к одному курсу, сколько бы раз модель ни переспрашивала.
- Заявка клиента найдена по контакту, даже если в диалоге перепутаны курсы — бот отвечает по данным `get_lead_details`.
- Старая база без колонок скидки — `initialize()` досоздаёт их при запуске, заявки сохранятся.
- MCP недоступен в момент напоминания — бот пишет предупреждение в лог и пробует позже, диалог не ломается.
- Длинный ответ — разбивается на части до лимита Telegram.
- Одинаковые быстрые сообщения из одного чата обрабатываются последовательно.

## Безопасность и ограничения

- MCP-сервер по умолчанию слушает только `127.0.0.1`; наружу порт не выставлен.
- Бот не принимает платежи и не хранит платёжные данные. Заявка — контакт, курс, промокод и итог без реквизитов.
- Валидируются имя, контакт, ID курса, ID заявки, промокод и срок рассрочки.
- Правила скидки и цены заказов считаются на сервере: модель не может «договорить» сумму, которой нет в ответе инструмента.
- Нет инструментов чтения файлов, выполнения команд и произвольного SQL — только операции из таблицы выше.
- Для учебного проекта авторизация MCP не настроена. Если открывать сервер в сеть, нужен reverse proxy и токен.
- Заявки содержат персональные данные. Перед реальным запуском нужны политика обработки ПДн и согласие пользователя.

## Возможные проблемы

**`MCP-сервер недоступен`**

Запустите `python run_server.py` или `python run_all.py`. Проверьте `MCP_URL` и что порт 8000 свободен:

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen
```

**`TelegramConflictError`**

С тем же `BOT_TOKEN` уже работает другая копия бота. Остановите её. Помогает перезапуск терминала и проверка процессов Python.

**Telegram не подключается**

Проверьте `TELEGRAM_PROXY`. Если прокси не нужен, оставьте переменную пустой. Ошибка `401 Unauthorized` означает неверный `BOT_TOKEN`.

**LLM возвращает ошибку**

Проверьте `OPENAI_API_KEY`, `OPENAI_BASE_URL` и название модели. Для ProxyAPI модели обычно указываются с префиксом провайдера, например `openai/gpt-4.1-mini`.

**Хочу сбросить базу**

Остановите сервер и удалите `data/courses.db` (и файлы `-wal`, `-shm`, если есть). При следующем запуске база создастся заново.

**PowerShell не активирует venv**

Выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, затем снова `.\venv\Scripts\Activate.ps1`. Можно вообще не активировать окружение и запускать `.\venv\Scripts\python.exe run_all.py`.

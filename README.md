# «ЛингваПро» — Telegram-бот продавца языковых курсов на MCP

Учебный проект: Telegram-бот на **aiogram 3**, который консультирует клиентов языкового центра и оформляет заявки. Все факты о курсах, ценах, скидках и условиях хранятся в **SQLite** и доступны боту только через **MCP-сервер** (Model Context Protocol).

Главная идея: LLM не «помнит» каталог и не получает его целиком в промпт. Модель решает, какой инструмент вызвать, а MCP-сервер возвращает компактный JSON. Это дешевле по токенам, чем RAG с большим контекстом, и исключает выдуманные цены.

---

## Что умеет бот

- подбирает курсы по языку, уровню и бюджету;
- показывает программу, преподавателя, длительность и свободные группы;
- считает цену с промокодом и рассрочкой (3/6/12 месяцев);
- отвечает на вопросы об оплате, пропусках, сертификате и формате обучения из базы знаний;
- создаёт заявку, когда у клиента есть имя, контакт и выбранный курс;
- не создаёт дубли заявок при повторном сообщении в течение 15 минут;
- ведёт короткую историю диалога отдельно для каждого чата;
- даёт выбрать длину ответа командой `/length` — отдельно для каждого чата;
- автоматически продолжает ответ, если модель остановилась по лимиту токенов;
- показывает каталог командой `/courses` напрямую через MCP, без вызова LLM.

Пример реального диалога:

> **Пользователь:** Хочу подтянуть разговорный английский. Сколько стоит и есть ли рассрочка?
>
> **Бот:** Курс «Разговорный английский» стоит 21 990 рублей. Рассрочка есть на 3, 6 и 12 месяцев. При рассрочке на 6 месяцев итоговая цена будет 23 090 рублей, ежемесячный платёж — 3 848 рублей. Хотите записаться?

## Архитектура

```text
Telegram
   │
   ▼
aiogram-бот (telegram_bot/)
   ├── handlers/        команды и сообщения
   ├── history.py       последние 12 сообщений на чат
   ├── preferences.py   выбранная длина ответа на чат
   └── agent.py         цикл LLM → tool call → ответ → продолжение
            │
            │ MCP Client (Streamable HTTP)
            ▼
MCP-сервер (mcp_server/)  http://127.0.0.1:8000/mcp
   ├── tools.py         6 инструментов
   ├── pricing.py       расчёт скидки и рассрочки
   ├── database.py      SQLite-запросы
   └── seed.py          стартовый каталог
            │
            ▼
      data/courses.db
```

Почему так:

- **одна ответственность** — бот не знает SQL, сервер не знает Telegram;
- **инструменты вместо RAG** — модель получает только нужные 2–5 записей, а не весь документ;
- **локальный сервер** — каталог и заявки остаются в локальной SQLite, без внешнего MCP-хостинга; текст диалога, как обычно, отправляется выбранному LLM-провайдеру;
- **честные ответы** — если инструмент вернул ошибку, модель обязана сказать об этом, а не придумать цену.

## MCP-инструменты

| Инструмент | Аргументы | Что возвращает |
|---|---|---|
| `search_courses` | `language`, `level`, `max_price` | компактный список курсов с `id`, ценой и длительностью |
| `get_course_details` | `course_id` | описание, программа, преподаватель, свободные группы |
| `calculate_course_price` | `course_id`, `promo_code`, `installment_months` | базовую цену, скидку, итог, платёж в месяц и доступные сроки рассрочки |
| `list_promotions` | — | активные промокоды и проценты |
| `search_faq` | `query`, `limit` | до 5 ответов из базы знаний |
| `create_lead` | `name`, `contact`, `course_id`, `preferred_time`, `comment` | ID заявки и признак дубля |

Все инструменты возвращают строку JSON с полем `ok`. Ошибки тоже оформлены как JSON: модель может объяснить их пользователю, а не падать.

### База данных

SQLite, файл `data/courses.db`, создаётся при первом запуске.

| Таблица | Назначение |
|---|---|
| `courses` | курсы: язык, уровень, цена, формат, длительность, преподаватель |
| `modules` | программа курса по модулям |
| `groups` | группы: расписание, свободные места, формат |
| `promos` | промокоды и скидки |
| `faq` | база знаний по обучению и оплате |
| `leads` | заявки клиентов |

Стартовые данные лежат в `mcp_server/seed.py`: 7 курсов, 21 модуль, 8 групп, 3 промокода и 12 вопросов FAQ. Повторный запуск не дублирует записи.

## Установка

Требуется **Python 3.10+** (проверено на 3.12).

### 1. Виртуальное окружение

Windows PowerShell:

```powershell
cd "C:\Users\user\Desktop\Zerocoder DZ\VPf08. MCP (Model Context Protocol)"
python -m venv venv
.\venv\Scripts\Activate.ps1
```

Если PowerShell блокирует активацию:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 2. Зависимости

```bash
pip install -r requirements.txt
```

Для тестов:

```bash
pip install -r requirements-dev.txt
```

### 3. Настройки

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен Telegram-бота от @BotFather |
| `OPENAI_API_KEY` | да | ключ ProxyAPI или другого OpenAI-совместимого API |
| `OPENAI_BASE_URL` | да | например `https://api.proxyapi.ru/v1` |
| `DEFAULT_MODEL` | да | основная модель, например `openai/gpt-4.1-mini` |
| `FALLBACK_MODEL` | нет | запасная модель при ошибке основной |
| `TELEGRAM_PROXY` | нет | прокси для Telegram, например `http://127.0.0.1:10809` |
| `MCP_URL` | нет | по умолчанию `http://127.0.0.1:8000/mcp` |
| `MCP_HOST`, `MCP_PORT` | нет | адрес MCP-сервера, по умолчанию localhost:8000 |
| `HISTORY_LIMIT` | нет | число сообщений истории, по умолчанию 12 |
| `MAX_TOOL_ROUNDS` | нет | максимум шагов агента, по умолчанию 5 |
| `MAX_CONTINUATIONS` | нет | сколько раз продолжать оборванный ответ, по умолчанию 2 |
| `PREFERENCES_FILE` | нет | файл настроек чатов, по умолчанию `data/preferences.json` |

`.env` уже добавлен в `.gitignore` и не должен попадать в репозиторий.

## Запуск

### Вариант 1: всё одной командой

```bash
python run_all.py
```

Скрипт поднимает MCP-сервер отдельным процессом, ждёт открытия порта и запускает бота. При выходе сервер останавливается. Если сервер уже запущен, второй экземпляр не создаётся.

### Вариант 2: два терминала

Терминал 1:

```bash
python run_server.py
```

Терминал 2:

```bash
python run_bot.py
```

Эквивалентные команды:

```bash
python -m mcp_server
python -m telegram_bot
```

При первом запуске автоматически появятся:

- `data/courses.db` — каталог, FAQ и заявки;
- `data/history.json` — история диалогов;
- `data/preferences.json` — выбранная длина ответов по чатам;
- `data/bot.log` — лог бота.

## Команды бота

| Команда | Действие |
|---|---|
| `/start` | приветствие и с чего начать |
| `/courses` | каталог и цены напрямую из MCP, без LLM |
| `/length` | длина ответов: `short`, `normal` или `long` |
| `/help` | возможности и список команд |
| `/clear` | очистить историю текущего чата |
| `/status` | статус MCP, история, длина ответов, модель |

Обычный текст уходит в агент. Нетекстовые сообщения получают вежливую подсказку.

### Длина ответов и автопродолжение

Команда `/length` действует только на текущий чат и сохраняется в `data/preferences.json`:

| Режим | Лимит ответа | Когда использовать |
|---|---|---|
| `short` | 350 токенов | короткая справка |
| `normal` | `DEFAULT_MAX_TOKENS` из `.env` (650) | обычный диалог |
| `long` | 1600 токенов | подробный разбор программы |

Примеры:

```text
/length
/length long
/length короткий
```

Если модель возвращает `finish_reason="length"`, агент автоматически просит продолжить ответ с места обрыва и склеивает части. Число продолжений ограничено `MAX_CONTINUATIONS`, поэтому даже «длинный» режим не может разрастись бесконечно. Если после всех продолжений ответ всё ещё обрезан, в конце добавляется многоточие, а в лог пишется предупреждение.

Важно: `/length` управляет длиной **ответа**, а не «окном контекста» модели. Память диалога по-прежнему ограничена `HISTORY_LIMIT` и `HISTORY_MAX_CHARS`.

### Ручной чек-лист в Telegram

1. `/start` — приходит приветствие.
2. `/courses` — список из 7 курсов с ценами.
3. `/length` — показывает текущий режим; `/length long` — подтверждает переключение.
4. Задайте подробный вопрос — длинный ответ приходит целиком, без обрыва на полуслове.
5. «Хочу разговорный английский, сколько стоит и есть рассрочка?» — бот называет 21 990 ₽ и варианты рассрочки.
6. «Какие курсы для начинающих до 18 000?» — бот предлагает «Английский с нуля»; при корректном фильтре также может предложить немецкий A1.
7. «Можно ли пропустить занятие?» — ответ про запись и отработку.
8. «Какие акции?» — активные промокоды из базы, без выдуманных условий.
9. «Меня зовут Ирина, телефон +7 999 123-45-67, запишите на разговорный английский вечером» — бот подтверждает и создаёт заявку.
10. Повторите заявку с тем же контактом — дубль не создаётся.
11. `/status` — MCP подключён, видно количество сообщений и режим длины.
12. `/clear` — история очищена, но выбранный режим `/length` сохраняется.

## Экономия токенов

Проект специально не использует RAG и тяжёлые фреймворки:

- в промпте нет каталога и FAQ — только правила продажи;
- 6 инструментов с короткими описаниями;
- результаты инструментов — компактный JSON без пробелов;
- результат обрезается до `MAX_TOOL_RESULT_CHARS` (5 000 символов);
- история ограничена 12 сообщениями и 9 000 символами;
- температура 0.3 и `max_tokens=650` в обычном режиме — ответы короче и стабильнее;
- режим `/length long` включается вручную и только для одного чата;
- автопродолжение работает не больше `MAX_CONTINUATIONS` раз;
- цикл инструментов ограничен 5 раундами, затем модель обязана ответить без вызовов;
- `/courses` вообще не тратит токены: бот форматирует ответ MCP сам.

## Устойчивость к ошибкам

- Нет MCP-сервера — бот запускается, `/start` и `/help` работают, на запросы отвечает понятным сообщением.
- Нет связи с LLM — пользователь получает «попробуйте ещё раз», подробности в `data/bot.log`.
- Telegram отклонил токен или запущена вторая копия — в логе понятная причина, процесс завершается.
- Битый `history.json` — история сбрасывается, бот продолжает работу.
- Битый `preferences.json` — настройки сбрасываются на `normal`, бот продолжает работу.
- Ответ оборвался по лимиту — агент автоматически продолжает его, но не больше `MAX_CONTINUATIONS` раз.
- Неверный промокод или срок рассрочки — инструмент возвращает JSON-ошибку, модель объясняет её.
- Повторная заявка — возвращается существующая запись, дубль не создаётся.
- Длинный ответ — разбивается на части до лимита Telegram.
- Одинаковые быстрые сообщения из одного чата обрабатываются последовательно.

## Безопасность и ограничения

- MCP-сервер по умолчанию слушает только `127.0.0.1`; наружу порт не выставлен.
- Бот не принимает платежи и не хранит платёжные данные. Заявка — только контакт и комментарий.
- Валидируются имя, контакт, ID курса, промокод и срок рассрочки.
- Нет инструментов чтения файлов, выполнения команд и произвольного SQL — только шесть описанных операций.
- Для учебного проекта авторизация MCP не настроена. Если открывать сервер в сеть, нужен reverse proxy и токен.
- Заявки содержат персональные данные. Перед реальным запуском нужны политика обработки ПДн и согласие пользователя.

## Возможные проблемы

**`MCP-сервер недоступен`**

Запустите `python run_server.py` или `python run_all.py`. Проверьте `MCP_URL` и что порт 8000 свободен:

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen
```

**`TelegramConflictError`**

С тем же `BOT_TOKEN` уже работает другая копия бота. Остановите её. Помогает перезапуск терминала и проверка процессов Python.

**Telegram не подключается**

Проверьте `TELEGRAM_PROXY`. Если прокси не нужен, оставьте переменную пустой. Ошибка `401 Unauthorized` означает неверный `BOT_TOKEN`.

**LLM возвращает ошибку**

Проверьте `OPENAI_API_KEY`, `OPENAI_BASE_URL` и название модели. Для ProxyAPI модели обычно указываются с префиксом провайдера, например `openai/gpt-4.1-mini`.

**Хочу сбросить базу**

Остановите сервер и удалите `data/courses.db` (и файлы `-wal`, `-shm`, если есть). При следующем запуске база создастся заново.

**PowerShell не активирует venv**

Выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, затем снова `.\venv\Scripts\Activate.ps1`. Можно вообще не активировать окружение и запускать `.\venv\Scripts\python.exe run_all.py`.
